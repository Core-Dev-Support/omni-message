# Omni Message — полный план разработки

Документ-дорожная карта «ультимативного» неофициального клиента Telegram.
Пакет: `com.naua_omni_message.app` · ABI: `armeabi-v7a` + `arm64-v8a` · База: форк [DrKLO/Telegram](https://github.com/DrKLO/Telegram) (GPL-2.0).
Контекст и исследование рынка — в [RESEARCH.md](RESEARCH.md).

> **Честное ограничение про «полную анонимность»:** Telegram привязывает аккаунт к номеру телефона, а серверы Telegram видят метаданные (кто, когда, с кем). Что реально сделать клиентом: скрыть всё, что видно собеседникам и каналам (статусы, прочтения, typing), не светить IP (прокси на весь трафик приложения), локально шифровать данные, резать телеметрию, поддерживать регистрацию через прокси + виртуальный номер, и продвигать секретные чаты (E2E) как режим по умолчанию для приватных переписок. Это максимум анонимности, достижимый клиентом без своего сервера.

## Этап A. Фундамент (недели 1–3)

Цель: воспроизводимая сборка форка и «скелет» проекта.

- [ ] **A1. Окружение.** Android Studio 2025.1.4, NDK 27.2.12479018, SDK 36, JDK 17. Диск ≥ 30 ГБ (репо с сабмодулями + сборочные артефакты).
- [ ] **A2. Клон апстрима.** `git clone --recursive --shallow-submodules https://github.com/DrKLO/Telegram`. Добавить remote `upstream` для будущих ребейзов.
- [ ] **A3. api_id.** Аккаунт на my.telegram.org (один api_id на номер; из РФ домен может не открываться — подготовить VPN на этот шаг). Не использовать sample-ключи из кода — иначе у пользователей будет `API_ID_PUBLISHED_FLOOD`.
- [ ] **A4. Ключи сборки.** Свой `release.keystore` → `TMessagesProj/config/`; в `gradle.properties` — `RELEASE_KEY_PASSWORD`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`. Keystore бэкапить (потеря = потеря обновлений у пользователей).
- [ ] **A5. Пробная сборка.** Flavor `Afat`, debug → APK на реальном устройстве. Проверить: вход, чаты, звонки, медиа.
- [ ] **A6. Свой Git-репозиторий.** Ветка `main` (наш код) + процедура ребейза на upstream (см. Этап H). README, LICENSE (GPL-2.0 унаследован), .gitignore.
- [ ] **A7. CI.** GitHub Actions: сборка debug+release APK на каждый PR и тег. Позже — reproducible builds (см. G).

## Этап B. Ребрендинг и каркас (недели 3–5)

Цель: приложение называется Omni Message, ставится рядом с официальным, обновляется.

- [ ] **B1. applicationId** → `com.naua_omni_message.app` (+ `com.naua_omni_message.app.beta` для бета-флейвора) в `TMessagesProj/build.gradle`. **Кодовый namespace `org.telegram.messenger` НЕ меняем** — это сильно упрощает ребейзы (стандартная практика форков).
- [ ] **B2. Имя, иконки, splash.** Строковые ресурсы, launcher-иконки всех плотностей, свой логотип (не самолётик — требование Telegram), экран загрузки.
- [ ] **B3. BuildVars.java.** Свой `APP_ID`/`APP_HASH`, выключить лишнее: `BUILD_APP_APPSTORE=false`, `TELEMETRY=false` и пр. dummy-значения из репо заменить все.
- [ ] **B4. Firebase.** Вариант 1 (проще): свой `google-services.json` без аналитики, только FCM-пуши. Вариант 2 (приватнее): выпилить FCM совсем — тогда пуши через фоновый сервис (проверить батарейку) — отложить решение до Этапа G.
- [ ] **B5. ABI-фильтры.** В `TMessagesProj/build.gradle`: `ndk { abiFilters "armeabi-v7a", "arm64-v8a" }` + в splits оставить только эти два (+ universal по желанию). APK легче апстримного минимум вдвое.
- [ ] **B6. Omni Settings — свой экран настроек.** Единая точка входа для всех наших фич (по образцу Cherrygram Preferences / exteraGram settings): `OmniConfig` (SharedPreferences + миграции), категории «Приватность», «Обход блокировок», «Оформление», «Фишки». Все тумблеры ниже живут здесь.
- [ ] **B7. In-app updater.** Проверка релизов на GitHub Releases, скачивание APK, проверка подписи, установка через PackageInstaller. Обновления — вопрос безопасности №1.

## Этап C. Приватность-ядро (недели 5–9) — «полная анонимность» в пределах возможного

Каждая фича — тумблер в Omni Settings, по умолчанию разумно-выключенные (ghost mode включённым не делаем: это ломает UX ожиданий собеседников и палится).

- [ ] **C1. Ghost mode (по AyuGram).** Три независимых переключателя:
  - «не отправлять прочтения» — подавить `messages.readHistory`/`readMentions` (в апстриме — `ChatActivity.markDialogAsRead` и связанные sendRequest) + локально помечать прочитанным только для себя;
  - «не показывать онлайн» — не слать `account.updateStatus` при выходе из app;
  - «не показывать набор текста» — не слать typing-действия (`SendMessagesHelper` typing actions), включая «записывает голосовое/загружает файл».
- [ ] **C2. Anti-recall (по AyuGram/CherryGram).** Перехватывать `updateDeleteMessages` (NotificationCenter → MessagesController): вместо удаления помечать сообщение локальным флагом «удалено у собеседника», показывать серым с подписью. Отдельно — защита медиа из «защищённых» контентов (сохранение картинок из чатов с запретом).
- [ ] **C3. Скрытие наблюдений:** не отправлять просмотры сторис (отдельно от прочтений), просмотры постов каналов, реакции «втихую» (опция), скрыть «вошёл в чат/покинул» служебные сообщения в отображении.
- [ ] **C4. Статус аккаунта:** скрыть номер телефона от всех (клиентская подмена отображения + серверная настройка privacy), скрыть «последний визит» жёстко, скрыть «читает/был недавно» — server privacy settings применяются при первом запуске одним пакетом.
- [ ] **C5. Локальный премиум.** Разлочить только клиентские проверки флага Premium (`UserConfig` current user premium + места проверок): эмодзи-статусы, аплоад со скоростью* (серверные лимиты не обойти — не обещать), дополнительные папки (клиентский лимит), анимированные эмодзи/аватары, транскрипция* (сервер — пометить как недоступное). *Честно документировать, что серверные фичи (4ГБ файлы, быстрее CDN) не поддельны.
- [ ] **C6. Экран чата:** «кто читал» без премиума — клиентский unlock; копирование текста из защищённых постов; сохранение запрещённого контента (см. C2); открытие ссылок без реферера.
- [ ] **C7. App-lock.** PIN/пароль + биометрия (BiometricPrompt) на вход; авто-блокировка по таймеру; блокировка отдельных чатов/папок паролем; «шторка» скрытия контента в рекents (FLAG_SECURE опционально).
- [ ] **C8. Локальная база.** Шифрование БД (SQLCipher или включение файлового шифрования апстрима) + `android:allowBackup=false`, exclude из автопереводов. Panic-действие: N неверных вводов → wipe локальной базы.
- [ ] **C9. Гигиена устройства:** `IME_FLAG_NO_PERSONALIZED_LEARNING` на поле ввода (клавиатура не учит слова), стрип EXIF при отправке фото (галочка, по умолчанию вкл), запрет скриншотов (опция), скрытие превью ссылок поисковикам (link preview off как дефолт для новых чатов).
- [ ] **C10. Сессии и входы:** панель «активные сессии» с kill-switch «завершить все кроме текущей», предупреждение при новом входе, автологаут неиспользуемых сессий (подсказка). 2FA-пароль и passphrase для cloud — подсказки-мастера при онбординге.
- [ ] **C11. Анти-фишинг:** подсветка ссылок с punycode/lookalike-доменов, показ полного URL перед открытием, предупреждение на «telegram-клоны» домены.
- [ ] **C12. Регистрация через прокси.** Онбординг: если регион РФ/прокси включён — регистрация сразу через прокси (IP не светится), возможность входа по QR/анонимному номеру (если доступно в API), подсказка про виртуальный номер.

## Этап D. Работа в РФ из коробки (недели 7–11, параллельно с C)

Цель: «установил — работает», без ручных прокси. Прозрачно (в отличие от «Телеги» — пользователь видит, что используется).

- [ ] **D1. Модуль `omni-connection`** (по образцу `vpn/` у vpGram): слой поверх `ConnectionsManager`/`SharedConfig` прокси-логики.
- [ ] **D2. Bootstrap-список прокси.** В APK зашит fallback: несколько MTProto-прокси (наши или доверенные публичные, секреты `ee`/`dd`). При старте: прямой коннект → если fail за N мс → авто-включение прокси.
- [ ] **D3. Живые списки по HTTPS.** Обновление списка прокси из GitHub raw / gist / нашего сайта (обычный HTTPS не блокируется), ротация, скоринг по пингу/потерям, авто-переключение при деградации. Формат — подписанный JSON (Ed25519), чтобы враждебные списки не подсунули свой прокси.
- [ ] **D4. DoH/DoT.** Резолвинг доменов прокси и служебных адресов через DNS-over-HTTPS (обход DNS-подмен РКН), кэш, fallback-резолверы.
- [ ] **D5. Kill-switch приложения.** Режим «весь трафик только через прокси»: предохранение от утечек при падении прокси (медиа идёт через те же ConnectionsManager-каналы — проверить CDN-адреса!), индикатор в шапке: «прямо / прокси / офлайн».
- [ ] **D6. Своя инфраструктура (фаза 2, когда будут деньги).** MTProto-proxy серверы вне РФ (mtg-совместимые), `ee`-секреты с fronting-доменами, запасные порты. Мониторинг доступности, метрики не собираем (логи минимум, без IP).
- [ ] **D7. Обход для звонков.** Звонки идут P2P/TURN — в РФ режутся; форсировать TURN через наши серверы/прокси, опция «звонки только через relay».
- [ ] **D8. Обновления из РФ.** GitHub может замедляться: зеркало списка прокси и апдейтов на нескольких доменах + через сами серверы Telegram (когда коннект есть).

## Definition of Done для v1.0

1. Устанавливается на Android 6+ (armv7 и arm64), работает рядом с официальным клиентом.
2. Из коробки подключается в РФ (прямой → прокси-фоллбек ≤ 5 с), есть индикатор канала связи.
3. Ghost mode, anti-recall, app-lock, EXIF-strip — работают, покрыты настройками.
4. Ноль сторонних трекеров (проверка трафика independent-сканером).
5. Сборка из публичных исходников воспроизводима, APK подписаны нашим ключом.
6. Обновления прилетают in-app, ребейз на апстрим ≤ 2 недель от security-фикса.

## Риски (кратко, детали в RESEARCH.md)

- **api_id могут отключить** за нарушения ToS — соблюдать правила, не злить Telegram (не возиться с серверными лимитами премиума).
- **GPL** — каждый распространяемый APK обязан сопровождаться исходниками.
- **Инфраструктура прокси** — главный операционный расход и точка отказа; публичные списки — временная мера.
- **Ребейзы** — форки умирают, когда перестают подтягивать security-фиксы апстрима; дисциплина из H4 обязательна с первого дня.
- **armv7** — собирать и тестировать отдельно (32-битные падения в нативных либах).
